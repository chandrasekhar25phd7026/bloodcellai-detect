# Browser detector and harmonizer (no backend, nothing uploaded)

`blood-cell-dataset-detector.html` is a single, self-contained page: open it in a browser, pick a dataset
folder or a `.zip`, and it runs the same frozen v1.4 / experimental v1.5 detector as the Python package
(ported to JavaScript; parity-tested against it) entirely client-side, then, for five formats, can build a
harmonized YOLO export you download as a `.zip`. No files are uploaded anywhere.

## What harmonization covers, and what it is ported from

`harmonize.js` ports the reusable parts of this project's earlier `bloodcell` Python package (the
universal image/box data model and the YOLO export logic, including its contiguous class-id remap) to
JavaScript, for: VOC XML, YOLO text, COCO JSON, classification folders, and point labels. Two deliberate
differences from that original code, both made for a public tool fed arbitrary datasets:

1. **Class names are discovered from the data itself**, not looked up in a hardcoded table. The original
   `parse_pascal_xml` silently dropped any class name outside a fixed 4-class list (and logged that it
   does so) — unacceptable for a tool that must work on datasets with any class vocabulary.
2. **Point-label box size is a fraction of each image's own decoded width**, not a hardcoded 70px on an
   assumed 640×480 canvas, so it scales across image sizes instead of silently mismatching them.

Segmentation masks and custom polygon/bounding-box JSON have no general harmonizer here (none existed in
the original package either); the page says so in plain words rather than guessing.

## What this does NOT include yet

This page covers detection (Section 4.1 of the paper) and harmonization/export (Section 2.1–2.6). The
**structural defect validator** (Section 4.3) and the **near-duplicate screen** (Section 4.4) were run from
scripts in the authors' own Kaggle notebooks and have not yet been cleaned into a releasable package —
that is real remaining work, tracked in the main `README.md`'s release notes, not something this page
or repository currently provides.

## Run the tests

```bash
cd web
npm install
npm test
```
Runs, in order: unit tests for the harmonization logic against hand-computed expected values
(`tests/test_harmonize.node.js`), then builds a jsdom-testable copy of the page
(`tests/make_test_html.js`), then full browser-simulation tests for detection
(`tests/e2e_detect.node.js`) and for harmonization (`tests/e2e_harmonize.node.js`) — real DOM events,
a real in-memory `.zip` built and read with JSZip, real XML parsing. `index.test.html` is generated by
the test run (git-ignored); it inlines a locally-installed JSZip only so the test can run without
network access — the real page always loads JSZip from the pinned CDN URL in its own `<script>` tag.
